# スキルの評価ハーネス

promptfooで「スキルあり」と「スキルなし」の計画出力を比較する。FSの個別起動、QAの実行不能、孫非対応の取り次ぎ、委任の深さ、起動不要の依頼、ライターの個別起動、権限の拡大防止を7ケースで検証する。

## 通常のCI

```sh
npm ci --prefix evals
npm run test:eval
npm run eval:smoke
```

`test:eval`は不正な出力を判定器が拒否することと、期待値がモデル用プロンプトへ漏れないことを確認する。`eval:smoke`は固定のfixtureを返してpromptfooの設定・判定・結果保存を確認する。モデルは呼ばず、この成功をスキルの品質評価として扱わない。

ハーネスの依存は`evals/package-lock.json`で分離している。文章lintだけを使う場合は、ルートでの`npm ci`のみでよい。

## 実モデルによる評価

利用できるプロバイダーと正確なモデルIDを明示する。既定モデルは設定していない。例えば`EVAL_PROVIDER`に、promptfooが対応する`openai:chat:モデルID`、`anthropic:messages:モデルID`、`ollama:chat:モデル名`のいずれかを設定する。

```sh
EVAL_PROVIDER='利用するプロバイダーとモデルID' npm run eval:live
```

必要なAPIキーやローカルモデルは、[promptfooのプロバイダー設定](https://www.promptfoo.dev/docs/providers/)に従って準備する。秘密は環境変数で渡し、コミットしない。モデルによっては呼び出しに費用が発生する。実行は1並列で、7ケースをスキルあり・なしの両方で評価する。

結果は`evals/results/live.json`に保存する。ローカルの結果フォルダはGit管理対象外。fixture結果と混同せず、使ったモデル・実行日・スコア・失敗理由を確認する。

## 評価できる範囲

これは文章としての計画出力の回帰検証。実際のサブエージェント起動、ツール権限、ファイル編集、Playwrightの打鍵は実行しない。JSON判定は役割・委任方式・深さ・未検証の扱いを確認し、自由記述の妥当性や成果物の質までは保証しない。

`cases.yaml`の期待値は判定側だけで使用する。ケース追加時は実際の依頼と環境条件を記載し、特定の文言を丸暗記させる評価にしない。失敗した評価を通すために、根拠なく期待値を緩めない。
