# Codex / Claude Codeでの起動

このパッケージは1つの移植可能なスキル。`npx skills add` はSKILL.mdと同梱参照を配置する。`.codex/agents`や`.claude/agents`へのカスタムエージェント登録、権限変更、深さ設定の変更は行わない。職能定義は実行時に利用可能な汎用サブエージェントへ渡すので、追加インストーラーは不要。

## ホストが選ぶ実行方法

1. 現在公開されている委任・通信・再開・終了ツールと実際の制限を確認する。ツール名や引数を他の製品から流用しない。
2. 孫を作れる場合: ホストがmanagerを起動し、managerが職能を起動する。元のホストをdepth 0として2まで。役割と深さを指示文にも記載する。
3. 子だけの場合: ホストがmanagerを起動。managerから委任要求を受け、ホストが担当を起動。成果をmanagerへ返して統合させる。この場合、組織上の配下と実行上の兄弟を区別する。
4. 通信できない／完了済みの担当を再開できない場合: その担当の成果と質問を次の呼び出しへ渡す。直接対話したと装わない。
5. サブエージェント自体がない場合: その制限を伝えて単独で進める。CLIを勝手に多重起動して制限を迂回しない。

実行枠はホスト・マネージャーを含めて確認する。職能の総数は同時実行数ではない。例えば合計4枠ならホスト1、manager1、職能2が同時に動ける上限となる。終了と解放の仕様はホストのツールに従う。

## Codex

利用可能なspawn、message、follow-up、wait、close相当のツールを使う。モデルや推論強度は明示要望がなければホスト設定を継承する。カスタムエージェント設定はこのスキルの前提としない。孫の生成や通信が制限されていれば、上の代行起動に切り替える。

```text
$product-team マネージャーに改善を任せ、必要な職能に実装と検証を分担して。
$product-team CS Opsだけ呼んで、更新前の支援フローを設計して。
```

## Claude Code

通常の会話で `/product-team` を呼ぶ。使えるAgent/Task相当の汎用エージェントへ指示文を渡す。入口に `context: fork` を固定せず、ホストがmanagerの起動を管理する。

子からのAgent利用や再開・メッセージの可否はバージョンと設定に依存する。古い環境も対象にし、委任要求をホストに返す方式を維持する。非対応のツール名を指定して起動しない。Agent Teamsの有効化を必須にしない。

```text
/product-team マネージャーに改善を任せて。QA設計とQA実行も分けて。
/product-team FSだけ呼んで、この案件の提案をまとめて。
```
