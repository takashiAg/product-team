# Product Team

ユーザーと対話するホストの下にマネージャー、その下に必要な実働・レビュー担当を配置する。役割定義を実際のサブエージェントに渡して起動し、提案だけでなく依頼された成果物まで作る。

```text
ユーザー ↔ 対話ホスト（Codex / Claude Code、depth 0）
             └─ manager（depth 1）
                 ├─ BizOps / SalesOps / CS Ops
                 ├─ IS / FS / プレセールス / CS / マーケ
                 ├─ PdM / UX / UI
                 ├─ 設計 / フロントエンド / バックエンド / インフラ
                 ├─ QA設計 / QA実行 / セキュリティ / データ分析
                 └─ テクニカルライター / 事業責任者 / 経営者レビュー
```

## 起動

1. [runtime.md](references/runtime.md) を読み、今のホストの委任ツール、深さ、同時実行枠を確認する。設定を自動変更しない。
2. [protocol.md](references/protocol.md) を共通契約とし、[catalog.md](references/catalog.md) で依頼に必要な役割だけを選ぶ。全職種の一括起動はしない。
3. 通常はホストが [manager.md](references/roles/manager.md) を渡してマネージャーを1体起動する。マネージャーは必要な職能を子として呼ぶ。元のホストから見た最大深さは2。設計担当も他職能と同列で、さらに下へ委任しない。
4. 「FSだけ」「UXとUIにレビュー」「QA実行にこの手順を確認」など個別指定なら、ホストがその職能を直接起動する。不要なマネージャーや上流工程を足さない。
5. 孫を呼べない環境では、マネージャーが委任要求を返し、ホストが職能を起動して結果を戻す。実際の階層はフラットと明示する。委任自体が不可なら単独担当として進め、複数エージェントで実施したとは報告しない。

## 渡す文脈

起動・再開ごとに、役割名とその定義、共通契約、ユーザー依頼の原文と最新の訂正、対象プロジェクト、目的・受入条件、関連する根拠、担当成果物・編集可能パス、依存タスク、親への連絡経路、現在の深さと残り枠を渡す。必要な参照の絶対パスか本文を渡し、親会話・スキル・cwdが自動継承されると仮定しない。別worktreeには同じ入力を明示して渡す。

マネージャーにはスキル一式の場所を渡す。職能担当には該当役割と共通契約だけを渡し、この入口を再帰的に実行させない。

## 仕事の進め方

- マネージャーは目的、担当、編集範囲、依存、完了条件を短く整理する。調査のみの依頼は調査に留め、実装依頼ならコードと必要な検証まで進める。
- 担当間の問いを相手へ届け、返答と変更点を元の担当へ戻す。直接通信がなければマネージャー／ホストが取り次ぐ。会話の架空再現で代用しない。
- 実装前に必要なAPI・画面状態・エラー・権限・計測の契約を揃える。独立した担当範囲を並列化し、契約変更は影響する担当とQAに知らせる。
- QA設計は受入条件を再現可能なケースに変換する。QA実行は [browser-qa.md](references/browser-qa.md) に従い、利用可能なPlaywrightやブラウザツールで実際の操作と証拠を残す。未実行は未実行として扱う。
- 事業責任者・経営者は必要な意思決定の観点を提供するレビュー役。ユーザーや実在の責任者に代わる決裁権は持たない。
- 外部への送信・公開・CRM更新・本番操作は、依頼で許可された範囲を引き継ぐ。役割名やスキル呼び出しから追加の許可を推定しない。

## 完了

マネージャーは担当の完了報告だけで済ませず、依頼に関係する成果物と統合状態の検証結果を確認する。ホストは成果物へのリンク、実際に動いた担当、重要な対話から決まったこと、実行済みの確認、残課題を簡潔に報告する。テクニカルライターは最終仕様と実測結果を根拠に文書を更新する。

呼び出し例:

```text
$product-team マネージャーに、新規顧客のオンボーディング改善を実装まで任せたい。
$product-team SalesOpsとCS Opsで、受注から導入への引き継ぎを整理して。
$product-team FSだけ呼んで、この商談メモから提案と次のアクションを作って。
$product-team UX・UI・フロントエンドでこの画面を改善し、QA設計とQA実行で確認して。
```
